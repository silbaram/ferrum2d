# 예제·데모 정리 (A: 보이는 구조 정리)

상태: 사용자 승인(방향 A), 1~5단계 완료, 예제 보기 화면 개선 1~5단계 완료(4-3 게임 데모·4-4 물리 실험실 상세 틀, 5 상세 화면 정리 포함). 기준일 2026-11-22, 기준 커밋 `7b23edb`,
작업 브랜치 `chore/examples-organization`.

AGENTS.md의 "구조 변경은 문서 합의 먼저" 규칙에 따라 범위와 순서를 먼저 정한다.
이번 정리는 **공개 URL·예제 폴더 이름·패키지 이름을 유지**하고, 사용자에게 보이는 구성과 이름을 정돈한다.
엔진 코어에 내장된 Breakout·Platformer·Shooter 규칙을 예제로 분리하는 일(방향 C)과 폴더 재배치(방향 B)는 범위 밖이다.

## 현재 구성

| 구분 | 항목 |
| --- | --- |
| 공개 앱 7개 | 엔진 기능 실험실(`starter-runtime`, 실험 31종·주제 10개), 물리 심화 실험실(`physics-sandbox`, 시나리오 7종), Breakout, Platformer, Neon Outpost(`topdown-shooter`), 작은 빛의 정원(`pixel-art`), Ferrum2D Studio |

| 코드 레시피 | `examples/data-scene-native` (엔진 문서가 링크하는 공개 API 레시피와 검증용 glTF, README 없음) |

`examples/README.md`와 `examples/shared/*Catalog.json`의 목록·개수는 서로 일치한다.
공개 Pages는 2026-11-12(`3c023eb`) 배포본이라 통합 물리 변경(#107, #110)을 반영하지 않았다.

## 정리가 안 돼 보이는 원인

1. 물리 시나리오의 이름 원본이 두 곳이다. 실험실은 `examples/shared/physicsExamples.json`("질량·마찰·반발" 등),
   물리 실험실은 자체 `examples/physics-sandbox/public/catalog.json`("강체와 재질 (Rigid Bodies & Materials)" 등)을 쓴다.
   같은 시나리오가 화면마다 다른 이름으로 보이고, 물리 실험실에는 영어 병기가 섞인다.
2. 물리 실험실은 다른 공개 앱과 화면 형식이 다르다. 캔버스에 영문 대문자 디버그 라벨이 겹쳐 그려지고
   (`RUBBER`, `ACTIVE` 등), 기능 실험실의 주제 탐색 없이 별도 앱처럼 보인다.
   실험실의 "물리" 주제는 이미 이 7종을 함께 연결한다.
3. 게임 표시 이름의 형식이 섞여 있다("충돌 반응 · Breakout", "전투 구성 · Neon Outpost", "도트 자산 · 작은 빛의 정원").
4. `data-scene-native`는 실행 앱이 아닌 코드 레시피인데 README와 목록 안내가 없어 역할이 보이지 않는다.
5. 실험 31종 중 HD-2D는 5종이며, 통합 3D 물리의 캐릭터·이동 발판·회전 CCD·군중·네이티브 저장 파일을
   직접 보여 주는 실험이 없다.

### 전체 검사에서 찾은 결함

데모 쪽에서 고친 것:

- 씬 전환 실험이 프레임 콜백 안에서 장면을 바꾸다 거부돼 암전에서 멈췄다. 전환을 프레임이 끝난 뒤로 미룬다.
- 저장·불러오기 실험과 HD-2D 그림자 대역 실험의 "재생 상태 JSON"은 JSON 진행 저장을 쓴다. 통합 물리에서는
  Data Scene 물리의 JSON 저장을 지원하지 않으므로 두 실험만 호환 물리로 실행한다.
- HD-2D 환경 실험의 그림자 검사가 혼합 조명에서 7번 그리기를 기대했다. 그림자는 조명별로 캐시되므로
  점광을 더하면 큐브 6면만 새로 그리고 태양 그림자는 재사용한다. 검사를 이 동작에 맞췄다.

엔진에서 고친 것과 고치는 것:

- 물리 재질 실험의 30Hz에서 공이 첫 벽 충돌 무렵 `UnresolvedMotion`으로 멈췄다(#107부터). 회전하는 중심 공의
  운동 승인을 고쳐 반영했다.
- 물리 실험실의 강체·충돌체·접촉·관절 시나리오가 약 2초 안에 `CapacityExceeded`로 멈춘다(#107부터). 센서
  쪽 원인 하나는 고쳤지만, 회전 상자 접촉의 운동 증명 한계는 물리 불변식을 바꾸는 설계 결정이 필요하다.
  [통합 3D 물리 계획](unified-3d-physics-plan.md#미해결-회전-상자-접촉의-운동-증명-2026-11-22)으로 분리했다.
  rigid 물리 설정은 엔진 backend와 무관하게 통합 물리를 쓰므로 호환 물리로 우회할 수 없다. 실험실은 멈추면
  "실행 중" 대신 오류와 원인을 표시하고, 실험실 smoke는 이 4개를 알려진 오류로 두고 나머지 3개의 무오류를 검사한다.
- `physics`를 생략한 HD-2D 장면의 heightSpan 주인공을 엔진 기본 native world가 거부했다. HD-2D 이동·AI 전투
  실험과 `data-scene-native/spatial.mjs` 레시피가 시작하지 못했다. 내장 장면에서 처음 전환하고 기본 물리 설정이
  그대로면 호환 물리로 실행하도록 고쳐 반영했다. 이미 native world로 실행 중인 Data Scene에 이런 문서를 다시
  적용하는 경우(예: Studio 같은 Engine의 편집→게임 재적용)는 여전히 거부하며, 실행한 world를 버릴지는 제품 결정이 필요하다.
- 통합 물리에서 `configureAutoRigidBodyStep({ ... })`가 중력을 바꿔도 `frame.physics` 중력 표시가 그대로였다
  (지형 파괴 실험 검사). native가 수용한 중력·연속 충돌을 표시하도록 SDK를 고쳤다.

네이티브 게임 파일로 바꾼 저장 실험은 복원한 Engine에 Data Scene 도구를 다시 연결하는 SDK 공개 API가 먼저
필요하다. 6단계 후보로 따로 진행한다.

## 예제 보기 화면 개선

### 배경

공개 사이트의 `/`는 기능 실험실로 바로 이동한다. 다른 예제로는 머리글의 "예제 이동" 드롭다운으로만 간다. 실험실의 주제·실험
목록은 같은 모양의 글자 버튼이라, 눌러 보기 전에는 무엇을 보여주는 실험인지 알기 어렵다. 2026-11-09에는 글자 카드로 된
이전 허브를 없애고 실험실로 바로 연결했다(실험실 탐색과 겹쳤다).

Phaser·Bevy·PixiJS·Defold 예제 사이트를 확인한 공통 방식은 다음과 같다. 카드마다 실제 화면 스크린샷·이름·한 줄 설명을 두고,
분류별로 묶어 개수를 보이며, 예제 페이지에서는 실행 화면 바로 아래에 소스와 이전/다음 이동을 둔다. 난이도 배지는 없다.

### 4-3단계 범위 (2026-11-23 사용자 승인)

게임 데모 4개(Breakout, Platformer, Neon Outpost, 작은 빛의 정원)의 상세 화면을 기능 실험실과 같은 틀로 맞춘다.

- 왼쪽 목록: 1280px 이상에서 게임 데모 4개를 썸네일과 함께 보이고, 지금 게임 아래에 그 게임의 '체험할 기능'을 둔다.
  실험실의 '주제 → 실험' 구조와 같다. 기능을 누르면 페이지를 다시 열지 않고 바뀌며 `?topic=`이 따라 바뀐다.
  더 좁으면 실행 화면 위의 선택 상자로 기능을 고른다. 다른 게임은 사이트 안에서만 링크한다(단독 실행은 지금 게임만).
- 실행 화면 위 '체험할 기능' 상자는 없앤다. 기능 이름은 실행 화면 위 소개 줄에, 조작·관찰 안내와 '이 위치에서 실험'·'충돌 영역'
  동작은 오른쪽 패널 맨 위에 둔다. 작은 빛의 정원은 체험할 기능 3개(길찾기·걷기, 노멀 조명, 팔레트·화면 효과)를 새로 정한다.
- 제목 줄·패널 테두리·폭·글꼴은 실험실과 같게 한다. 제목은 카탈로그 이름(`<게임 이름> · <배우는 기능>`)이다.
  캔버스 안 HUD·시작 화면과 패널 내용(작전 브리핑, 씨앗 찾기 등)은 그대로 둔다.
- 실행 화면 아래에 코드 보기(Game Spec·씬 JSON이 있으면 그 탭, API, 코드 위치)와 이전/다음 게임을 둔다.

### 5단계 범위 (2026-11-23 사용자 승인)

4단계까지 틀은 통일했지만 단계마다 설명 상자가 더해졌다. 노멀맵 실험 하나에 설명 글이 9곳(머리글의 예제 안내, 확인할 것,
사용 안내, 비교 카드와 설명, 범례, 강조 상자, 힌트 줄, 엔진 실행 정보)이고, 물리 실험실은 시나리오 이름이 4번 나오며
1440px 화면에서 글 약 3,700자·높이 1,930px다. 수치와 코드도 처음부터 펼쳐져 있다. 시안(`calm.html`)으로 확인한 방향은 다음과 같다.

**원칙.** 상세 화면은 처음에 세 가지만 보인다. 무엇인지(제목과 한 문장), 해 보기(버튼·조작·설정), 볼 것(짧은 문장 2~3개).
나머지(설명, 코드, 엔진 수치, 물리 설정·신호, 게임 브리핑)는 레이아웃 아래 '더 보기'에 접는다. 같은 말은 한 번만 쓴다.

공용(`examples/shared/`):

- 머리글: 상세 틀 페이지(기능 실험실·물리 실험실·게임 데모)는 '예제 안내' 줄 대신 경로 한 줄을 둔다
  (`Ferrum2D 예제 › 기능 실험 › 조명·그림자`). 참고용 페이지(`reference`)는 지금처럼 '예제 안내'를 둔다.
  게임·물리 실험실의 관련 기능 실험 링크와 단독 실행 안내는 '더 보기 › 설명'으로 옮긴다.
- 제목 줄(`.demo-toolbar`)과 소개 줄(`.example-intro`)을 실행 화면 위 한 줄로 합친다. 제목(h1), 한 문장, 오른쪽 실행 버튼
  (기능 실험실·물리 실험실의 일시정지·처음으로 등은 아이콘, 이름은 `aria-label`). 게임 데모의 실행 버튼은 상태에 따라 이름이 바뀌는
  공용 runtime shell 버튼('다시 시작'·'처음부터')이라 글자를 유지하고 크기만 줄인다. 작은 주황 이름표('확인할 것', '체험할 기능 · 1/2',
  '시나리오 · 1/7')는 없앤다. 공용 조각은 `examples/shared/exampleFrame.ts`(제목 줄·아이콘 버튼·해 보기·볼 것·접기)에 둔다.
- 패널: 테두리 없이 '해 보기'와 '볼 것' 두 묶음. 목록도 테두리를 없애고, 실행 화면만 테두리를 둔다.
- 이전/다음: 레이아웃 아래 큰 상자 두 개 대신 실행 화면 바로 아래 한 줄 링크.
- 더 보기: 코드 보기를 '더 보기'로 바꾸고 처음에는 닫는다. 탭을 누르면 그 탭으로 펼쳐진다. 탭은 설명, 데이터 파일, API,
  코드 위치와 페이지별 수치 탭이다. 데이터 파일은 탭을 처음 열 때 불러온다. 3단계에서 코드 보기를 항상 펼쳐 두던 것을 바꾼다.
- 폭과 칸 간격(16px)은 4단계와 같다(1280px 이상 `232px | 실행 화면 | 304px`, 최대 1520px). 간격을 24px로 넓히면 실행 화면이
  16px 좁아져 고정 800px 게임 화면과 HD-2D 그림자 픽셀 검사가 깨져 유지했다. 700px 이하 기능 실험실은 실행 화면을 위에 고정하고
  해 보기·볼 것을 화면 절반 높이의 패널 안에서 스크롤한다.

기능 실험실(31개, HD-2D 공간 실험 포함):

- 제목은 실험 이름, 한 문장은 카탈로그 `summary`.
- 해 보기: 지금의 설정 폼, 실행 화면 위에 있던 주요 동작 버튼(`lesson.actions`)을 맨 위에. 캔버스 조작 힌트는 실험별 힌트가
  있을 때만 한 줄로 둔다('설정을 바꾸며 같은 장면의 변화를 비교하세요.' 같은 공통 문구는 없앤다).
- 볼 것: 카탈로그 `observe`를 문장 단위 목록으로 보인다. 31개 모두 1~2문장이라 `observe`는 바꾸지 않았다.
- 실험실과 HD-2D 공간 실험이 각자 만들던 틀은 `examples/starter-runtime/src/featureFrame.ts` 하나로 합친다.
- 더 보기 › 설명: 쓰는 상황(`useCase`), 장면(`scenario`), 순서(`steps`), 화면 읽는 법(`legend`), 비교 카드와 실시간 안내 줄.
  캔버스 위에 겹치는 상태판(에셋 불러오기·스트리밍)과 역할 라벨은 실행 화면에 그대로 둔다.
- 더 보기 › 엔진 수치: 실시간 관찰 값과 오브젝트·그리기 명령·드로우 콜.

게임 데모(4개, 체험할 기능 9개):

- 제목은 체험할 기능 이름, 한 문장은 기능마다 새로 쓰는 짧은 설명. 경로에 게임 이름을 둔다.
- 해 보기: 조작 문장, '이 위치에서 실험'·'충돌 영역' 동작, 게임 조작(작은 빛의 정원의 씨앗 버튼 등). 화면·소리 설정처럼
  보조 설정은 접어 둔다. 캔버스 아래 조작 힌트 줄은 해 보기와 겹쳐 없앤다.
- 볼 것: 기능의 `observe`를 문장 단위 목록으로.
- 더 보기: 게임 설명(Neon Outpost 작전 브리핑처럼 시작 화면과 겹치는 설명, 관련 기능 실험 링크), 데이터 파일, API, 코드 위치,
  엔진 수치(Breakout·Platformer의 상태·점수·객체 수 등).
- 캔버스 안 HUD·시작 화면과 게임 규칙은 그대로다.

물리 심화 실험실(시나리오 7개):

- 경로 `Ferrum2D 예제 › 물리 심화 실험실 › 분류`. 제목은 시나리오 이름과 작은 '알려진 문제' 표시(내용은 `title`), 한 문장은 `summary`.
  목록의 알려진 문제는 빨간 점으로 표시한다.
- 실행 버튼: 실행·일시정지·한 프레임·리셋 아이콘과 작은 상태 표시. 캔버스 아래 디버그 표시 선택은 한 줄로 둔다.
- 해 보기: 시나리오 동작 버튼, '재질 값 바꾸기'(재질 조절을 접어 둠), 캔버스에서 고른 물체의 상태.
- 볼 것: 시나리오의 관찰 포인트.
- 더 보기: 설명(실험실 목적·관련 기능 실험·알려진 문제 전문), Physics Spec, API, 코드 위치, 엔진 수치. 다른 상세 화면과 같도록
  실행 상태(경고 포함)·물리 설정·물리 신호·마지막 오류는 엔진 수치 탭 하나에 둔다.
- 실행이 멈추면 큰 오류 상자 대신 실행 화면 아래 한 줄로 알리고, '자세히'가 엔진 수치 탭을 연다. 코드와 메시지는 그 탭에 둔다.
- 물리 실행과 시나리오 데이터(관찰 문장 제외)는 바꾸지 않는다.

순서와 검증: 공용 틀과 기능 실험실(5-1), 게임 데모(5-2), 물리 실험실(5-3) 순서로 고치고, 끝난 상태에서 한 번 검증했다.
`pnpm smoke:feature-examples`·`smoke:example-suite`·게임별·물리 smoke의 화면 구조 검사를 새 틀에 맞추고, 1440×900에서 제목·실행 화면·
해 보기·볼 것이 첫 화면에 들어오는지, 더 보기가 닫혀 있는지, 390/320px 넘침이 없는지 확인한다.

### 1단계 범위

- 빌드할 때 `exampleCatalog.json`·`featureCatalog.json`·`featureTopics.json`·`physicsExamples.json`에서 갤러리 HTML을

## 유지하는 것과 이유

- `minimal-game`: 렌더 smoke 10여 개가 `@ferrum2d/minimal-game`으로 빌드해 사용한다. 이동 비용 대비 이득이 작아 위치를 유지하고, 메뉴에서는 지금처럼 숨긴다.
- `?mode=playground`, `?mode=starter`: 회귀 검사가 사용하며 이미 메뉴에서 숨긴다. URL과 코드를 유지한다.
- 예제 폴더·패키지 이름과 Pages 주소(`starter-runtime/`, `physics-sandbox/` 등): 공개 링크와 스크립트를 깨지 않는다.
