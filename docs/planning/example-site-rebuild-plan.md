# 예제 사이트 다시 만들기

상태: 사용자 승인(2026-11-23), 1단계(사이트 틀) 완료. 다음은 첫 예제 추가. 기준 커밋 `845cc29`(PR #112 머지).
[예제·데모 정리](examples-organization-plan.md)의 '예제 보기 화면 개선'(1~5단계)을 이 계획이 대체한다.

AGENTS.md의 "구조 변경은 문서 합의 먼저" 규칙에 따라 범위와 순서를 먼저 정한다.

## 배경

5단계까지 다듬은 상세 화면도 목록·실행 화면·글 칸을 나란히 둔 문서형 페이지였고, 실행 화면은 폭의 약 57%였다.
다른 엔진 예제 사이트(PlayCanvas, three.js, Bevy, Rapier, Matter.js, PixiJS, Phaser, Babylon.js)를 비교한 결과,
잘 만든 곳은 실행 화면이 페이지의 대부분을 차지하고, 조작은 작은 설정 행으로, 설명은 제목 한 줄과 버튼 뒤로 보낸다.
Pixelforge 디자인 체계의 기본 레이아웃(상단 막대·왼쪽 목록·가운데 뷰포트·오른쪽 인스펙터·아래 패널·상태 막대)이 같은 구조라
그 틀로 처음부터 다시 만든다. 시안은 편집기형(`mock3`)이다.

## 결정 (2026-11-23 사용자 승인)

- 예제 사이트를 처음부터 다시 만든다. 먼저 사이트 전체 틀만 만들고, 예제는 하나씩 추가한다.
- 기존 예제(엔진 기능 실험실, 물리 심화 실험실, 게임 데모 4개)와 예제 갤러리는 공개 사이트에서 뺀다.
  예제 폴더는 엔진 검사 데이터로 남기고 공개하지 않는다. `topdown-shooter`는 Game Spec·골든 데이터로 테스트·스크립트·CI 31곳에서,
  `minimal-game`은 렌더 smoke에서, `physics-sandbox`의 Physics Spec은 Rust 물리 테스트에서 읽는다.
  예제를 다시 넣을 때 필요한 코드만 옛 폴더에서 가져오고, 쓰지 않게 된 폴더는 검사 의존을 옮긴 뒤 따로 정리한다.
- Studio(제작 도구)와 문서 사이트는 지금처럼 발행한다.

## 화면

- 넓은 화면은 창 높이에 고정하고 패널마다 따로 스크롤한다(편집기·PlayCanvas와 같다).
- 상단 막대(40px): 로고, 지금 위치 경로, 예제 검색, 문서, GitHub.
- 왼쪽 예제 목록(264px): 게임 데모·기능 실험·물리·도구 분류 트리. 선택은 Pixelforge 표식(앰버 왼쪽 선과 옅은 채움)이다.
- 가운데: 첫 화면은 예제 카드 격자다. 예제가 아직 없으면 준비 중 안내와 문서·Studio·이전 예제 코드(GitHub) 링크를 둔다.
- 예제 화면(첫 예제와 함께 확정): 재생 막대(실행·일시정지·리셋, 이전/다음, 렌더러, 전체 화면), 격자 배경 위 실행 화면,
  아래 패널(설명·데이터 파일·API·소스·엔진 탭, 처음에는 접힘), 오른쪽 인스펙터(예제 이름·한 문장, 해 보기 설정 행, 볼 것),
  하단 상태 막대(렌더러·FPS·엔진 수치).
- 900px 이하는 한 줄로 쌓고 예제 목록은 ☰ 서랍으로 연다. 예제 화면은 실행 화면 → 해 보기·볼 것 → 아래 패널 순서다.
- Pixelforge 토큰, Lucide 아이콘 일부(ISC), Noto Sans KR 부분집합을 쓴다. 외부 글꼴·CDN은 쓰지 않는다.

### 예제 화면 상세 (승인한 시안 기준)

시안 HTML은 저장소에 두지 않았다(세션 임시 폴더). 예제 화면은 이 절을 기준으로 만든다.

- 칸 너비: 예제 목록 264px · 가운데 나머지 · 인스펙터 312px. 첫 화면에는 인스펙터가 없다.
- 재생 막대(36px, 실행 화면 위): 왼쪽에 아이콘 버튼 묶음(실행·일시정지·한 프레임·리셋 중 예제에 맞는 것), 그 옆에 지금 예제 이름 탭
  (실행 상태 점: 실행 초록, 오류 빨강). 오른쪽에 렌더러 선택·이전/다음 예제·전체 화면. 물리처럼 디버그 표시가 있으면 '표시' 메뉴(체크 목록)를 둔다.
- 실행 화면: 격자 배경(`--viewport-bg`, 32px 격자) 가운데에 캔버스를 비율 유지로 최대한 크게. 캔버스 안 HUD는 예제 것을 그대로 둔다.
- 아래 패널: 탭 줄(32px)만 보이고 접혀 있다. 탭을 누르면 240px로 열리고 다시 누르면 닫힌다. 탭은 설명·데이터 파일(씬 JSON/Game Spec/Physics Spec)·
  API·소스·엔진. 설명 탭은 쓰는 상황·해 보는 순서·화면 읽는 법·비교 카드, 엔진 탭은 실행 상태·설정·신호 등 자세한 수치다.
- 인스펙터: 머리(분류 경로 한 줄, 예제 이름, 한 문장, 알려진 문제가 있으면 빨간 표시) 아래 접을 수 있는 구역. '해 보기'는 이름 76px +
  조작(분할 버튼·스위치·선택 상자·슬라이더+숫자) 설정 행과 동작 버튼, 캔버스 조작 힌트 한 줄. 보조 설정(화면과 소리, 재질 값)은 접힌 구역.
  '볼 것'은 짧은 문장 2~3개 목록. 물리의 '선택한 물체'는 이름·값 행 구역이다.
- 상태 막대(24px): 렌더러·FPS·오브젝트·그리기 명령·드로우 콜처럼 늘 보는 엔진 수치. 알려진 문제는 노란 경고 한 줄로 덧붙인다.
- 게임의 '체험할 기능'은 예제 목록에서 게임 아래 하위 행으로 고른다.

## 구조

- 새 앱 `examples/site`(`@ferrum2d/example-site`)가 사이트 틀과 예제 목록을 가진다. Pages 첫 화면(`/`)으로 발행한다.
  예제는 이 앱 안의 모듈로 추가해 같은 틀 안에서 `?example=<id>`로 연다. 예제를 바꿔도 틀은 다시 그리지 않는다.
- 예제 모듈 계약(실행 화면·인스펙터·아래 패널·상태 막대에 무엇을 넘기는지)은 첫 예제를 넣으며 정한다. 쓰는 예제가 없는 계약은 미리 만들지 않는다.
- 옛 주소(`/starter-runtime/`, `/breakout/`, `/platformer/`, `/topdown-shooter/`, `/pixel-art/`, `/physics-sandbox/`)는
  새 첫 화면으로 보내는 안내 페이지로 남겨 외부 링크가 404가 되지 않게 한다.
- `build-pages`는 예제 앱 대신 `examples/site/dist`를 루트에 복사하고, Studio와 문서는 지금처럼 만든다.
  갤러리 생성기(`scripts/build/example-gallery.mjs`, `examples/shared/gallery/gallery.*`)와 그 테스트, 발행된 예제에서 썸네일을 찍던
  `pnpm thumbnails:examples`는 지운다. 옛 예제 앱이 쓰는 카탈로그·썸네일은 검사 데이터로 남긴다.
- 검사: 옛 사이트 통합 검사 `smoke:example-suite`는 새 사이트 검사 `smoke:example-site`로 바꾼다. 옛 예제 앱의 smoke
  (`smoke:feature-examples`, 게임·물리 렌더 smoke)는 검사 데이터로서 그대로 둔다. Pages 산출물 검사와 배포 후 경로 검사는
  새 첫 화면·Studio·문서·옛 주소 안내로 바꾼다.

## 다음 진행 (2026-11-23 기준)

- 1단계 변경은 아직 커밋하지 않았다(작업 트리 `main`). 커밋·푸시와 Pages 배포 시점은 사용자가 정한다.
  배포하면 공개 사이트에는 예제 없이 틀만 보인다.
- 첫 예제를 사용자와 고른다. 권장은 작은 기능 실험 하나(예: 노멀맵과 점광원, `examples/starter-runtime`의 `lighting`)다.
  첫 예제를 넣으며 할 일:
  1. 위 '예제 화면 상세'대로 재생 막대·실행 화면·인스펙터·아래 패널·상태 막대를 만든다.
  2. 예제 모듈 계약을 정한다(예제가 받는 것: 캔버스·인스펙터 구역·아래 패널 탭·상태 막대 항목·수명 주기 신호. 예제가 돌려주는 것: 정리 함수).
  3. 옛 폴더에서 그 예제에 필요한 코드·씬 파일·에셋만 `examples/site`로 가져온다(옛 폴더는 검사 데이터로 그대로 둔다).
  4. `smoke:example-site`에 그 예제의 화면·조작·수명 주기(시작 중 이동·자원 해제) 검사를 더한다.
  5. README·기능 안내 문서에서 그 예제의 옛 링크를 새 주소(`?example=<id>`)로 바꾼다.
- 별도 후보: 엔진 `createFerrumRuntime`의 크기 감시가 Wasm 로딩 중 이미 정리된 렌더러에 `resize`를 한 번 부를 수 있다(드문 타이밍 경합).
  공개 패키지 변경이라 따로 진행한다.

## 검증

- 1단계: `pnpm lint`, 새 사이트 빌드, `pnpm build:pages`, `pnpm validate:pages-artifact`, `pnpm smoke:example-site`
  (첫 화면·목록·검색·서랍·없는 예제 안내·옛 주소 안내·1440/1024/390/320px 넘침 없음·JavaScript 오류 없음),
  남겨 둔 예제 검사 데이터를 쓰는 smoke가 그대로 통과하는지.
- 옛 사이트 통합 검사(`smoke:example-suite`)가 하던 이전 예제 앱의 Pages 수명 주기 검사(시작 중 취소·자원 해제·시나리오 요청 순서)는
  그 앱들이 발행되지 않으므로 함께 지웠다. 기능 실험실의 수명 주기·복구 검사는 `smoke:feature-examples`에 남아 있고,
  새 사이트에는 예제를 추가할 때 그 예제의 수명 주기 검사를 함께 넣는다.
- README와 기능 안내 문서의 옛 공개 실험 링크(약 100개)는 새 첫 화면으로 이동하므로 문서 위에 안내를 달았다. 예제가 다시 들어올 때 링크를 바꾼다.
- GitHub Pages 재배포는 원격 상태 변경이므로 사용자가 진행하거나 별도 승인 후 진행한다.
