# 예제 사이트 다시 만들기

상태: 사용자 승인(2026-11-23), 1단계(사이트 틀) 완료. 예제 목록·분류 확정(2026-11-24). 예제 '스프라이트 그리기'·'충돌과 트리거'·'벽돌 깨기'를 넣었다.
기준 커밋 `845cc29`(PR #112 머지).
[예제·데모 정리](examples-organization-plan.md)의 '예제 보기 화면 개선'(1~5단계)을 이 계획이 대체한다.

AGENTS.md의 "구조 변경은 문서 합의 먼저" 규칙에 따라 범위와 순서를 먼저 정한다.

## 배경

5단계까지 다듬은 상세 화면도 목록·실행 화면·글 칸을 나란히 둔 문서형 페이지였고, 실행 화면은 폭의 약 57%였다.
다른 엔진 예제 사이트(PlayCanvas, three.js, Bevy, Rapier, Matter.js, PixiJS, Phaser, Babylon.js)를 비교한 결과,
잘 만든 곳은 실행 화면이 페이지의 대부분을 차지하고, 조작은 작은 설정 행으로, 설명은 제목 한 줄과 버튼 뒤로 보낸다.
Pixelforge 디자인 체계의 기본 레이아웃(상단 막대·왼쪽 목록·가운데 뷰포트·오른쪽 인스펙터·아래 패널·상태 막대)이 같은 구조라
그 틀로 처음부터 다시 만든다. 시안은 편집기형(`mock3`)이다.

## 결정 (2026-11-23 사용자 승인)

- 예제 사이트를 처음부터 다시 만든다. 먼저 사이트 전체 틀만 만들고, 예제는 하나씩 추가한다.
- 기존 예제(엔진 기능 실험실, 물리 심화 실험실, 게임 데모 4개)와 예제 갤러리는 공개 사이트에서 뺀다.
  예제 폴더는 엔진 검사 데이터로 남기고 공개하지 않는다. `topdown-shooter`는 Game Spec·골든 데이터로 테스트·스크립트·CI 31곳에서,
  `minimal-game`은 렌더 smoke에서, `physics-sandbox`의 Physics Spec은 Rust 물리 테스트에서 읽는다.
  예제를 다시 넣을 때 필요한 코드만 옛 폴더에서 가져오고, 쓰지 않게 된 폴더는 검사 의존을 옮긴 뒤 따로 정리한다.
- Studio(제작 도구)와 문서 사이트는 지금처럼 발행한다.
- 예제는 옛 목록을 옮기지 않고, 필수 기능을 눈으로 확인하는 기준으로 새로 정한 목록(아래 '예제 목록')으로 채운다(2026-11-24 승인).
  옛 폴더의 코드·에셋은 필요할 때 참고하거나 복사만 한다.

## 예제 목록 (2026-11-24 승인)

기준: 한 예제에 기능 하나, 조작하면 화면이 바로 바뀌고, 엔진이 실제로 한 일은 상태 막대 수치로 확인한다.
씬 JSON은 모든 예제의 '씬 파일' 탭에서 보여 주므로 따로 예제로 만들지 않는다. 목록 분류도 이 묶음을 그대로 쓴다.

## 화면

- 넓은 화면은 창 높이에 고정하고 패널마다 따로 스크롤한다(편집기·PlayCanvas와 같다).
- 상단 막대(40px): 로고, 지금 위치 경로, 예제 검색, 문서, GitHub, 한국어·영어 선택.
- 왼쪽 예제 목록(기본 264px, 너비 조절·접기): 위 '예제 목록'의 분류 트리. 선택은 Pixelforge 표식(앰버 왼쪽 선과 옅은 채움)이다.
- 가운데: 첫 화면은 예제 카드 격자다. 예제가 아직 없으면 준비 중 안내와 문서·Studio·이전 예제 코드(GitHub) 링크를 둔다.
- 예제 화면(첫 예제와 함께 확정): 재생 막대(실행·일시정지·리셋, 이전/다음, 렌더러, 전체 화면), 격자 배경 위 실행 화면,
  아래 패널(설명·데이터 파일·API·소스·엔진 탭, 처음에는 접힘), 오른쪽 인스펙터(예제 이름·한 문장, 해 보기 설정 행, 볼 것),
  하단 상태 막대(렌더러·FPS·엔진 수치).
- 900px 이하는 한 줄로 쌓고 예제 목록은 ☰ 서랍으로 연다. 예제 화면은 실행 화면 → 해 보기·볼 것 → 아래 패널 순서다.
- Pixelforge 토큰, Lucide 아이콘 일부(ISC), Noto Sans KR 부분집합을 쓴다. 외부 글꼴·CDN은 쓰지 않는다.

### 예제 화면 상세 (승인한 시안 기준)

시안 HTML은 저장소에 두지 않았다(세션 임시 폴더). 예제 화면은 이 절을 기준으로 만든다.

- 칸 너비: 예제 목록 264px · 가운데 나머지 · 인스펙터 312px(처음 크기). 첫 화면에는 인스펙터가 없다.
- 패널 크기와 접기(넓은 화면만, 2026-11-24 사용자 요청): 목록·인스펙터·아래 패널은 경계선을 끌어 8px 단위로 크기를 바꾼다.
  목록 200~480px(창의 40%까지), 인스펙터 264~560px, 아래 패널 120px부터이고, 실행 화면은 가로 320px·세로 160px을 남긴다.
  경계선은 화살표(Shift는 크게)·Home·End로도 조절하고, 두 번 누르면 처음 크기로 돌아간다.
  목록과 인스펙터는 바깥 모서리 버튼으로 36px 아이콘 줄로 접는다. 접힌 줄의 아이콘(목록은 분류, 인스펙터는 해 보기·볼 것)을 누르면 펼쳐 그 자리로 간다.
  크기와 접힘은 이 브라우저에 저장하고(`site/src/layout.ts`), 아래 패널이 열렸는지는 저장하지 않는다. 900px 이하에서는 쓰지 않는다.
- 재생 막대(36px, 실행 화면 위): 왼쪽에 아이콘 버튼 묶음(실행·일시정지·한 프레임·리셋 중 예제에 맞는 것), 그 옆에 지금 예제 이름 탭
  (실행 상태 점: 실행 초록, 오류 빨강). 오른쪽에 렌더러 선택·이전/다음 예제·전체 화면. 물리처럼 디버그 표시가 있으면 '표시' 메뉴(체크 목록)를 둔다.
- 실행 화면: 격자 배경(`--viewport-bg`, 32px 격자) 가운데에 캔버스를 비율 유지로 최대한 크게. 캔버스 안 HUD는 예제 것을 그대로 둔다.
- 아래 패널: 탭 줄(32px)만 보이고 접혀 있다. 탭을 누르면 열리고(처음 240px) 다시 누르면 닫힌다. 탭은 설명·데이터 파일(씬 JSON/Game Spec/Physics Spec)·
  API·소스·엔진. 설명 탭은 쓰는 상황·해 보는 순서·화면 읽는 법·비교 카드, 엔진 탭은 실행 상태·설정·신호 등 자세한 수치다.
- 인스펙터: 재생 막대와 높이를 맞춘 줄(분류 경로, 접기 버튼), 머리(예제 이름, 한 문장, 알려진 문제가 있으면 빨간 표시) 아래 접을 수 있는 구역. '해 보기'는 이름 76px +
  조작(분할 버튼·스위치·선택 상자·슬라이더+숫자) 설정 행과 동작 버튼, 캔버스 조작 힌트 한 줄. 보조 설정(화면과 소리, 재질 값)은 접힌 구역.
  '볼 것'은 짧은 문장 2~3개 목록. 물리의 '선택한 물체'는 이름·값 행 구역이다.
- 상태 막대(24px): 렌더러·FPS·오브젝트·그리기 명령·드로우 콜처럼 늘 보는 엔진 수치. 알려진 문제는 노란 경고 한 줄로 덧붙인다.
- 게임의 '체험할 기능'은 예제 목록에서 게임 아래 하위 행으로 고른다.

## 구조

- 새 앱 `examples/site`(`@ferrum2d/example-site`)가 사이트 틀과 예제 목록을 가진다. Pages 첫 화면(`/`)으로 발행한다.
  예제는 이 앱 안의 모듈로 추가해 같은 틀 안에서 `?example=<id>`로 연다. 예제를 바꿔도 틀은 다시 그리지 않는다.
- 예제 모듈 계약(실행 화면·인스펙터·아래 패널·상태 막대에 무엇을 넘기는지)은 첫 예제를 넣으며 정한다. 쓰는 예제가 없는 계약은 미리 만들지 않는다.
  첫 예제에서 정한 계약:
  - 카탈로그 항목(데이터): 이름·한 문장·분류, 월드 크기(캔버스 비율), 볼 것 문장, 설명 탭 글, API 목록, 소스 경로, 모듈 불러오기 함수(예제별 코드 분할).
  - 예제가 받는 것: 캔버스, 고른 렌더러, 수명 신호(`AbortSignal`, 예제를 떠나거나 렌더러를 바꾸면 중단), '해 보기' 구역에 설정 행을 만드는 도구,
    씬 파일 탭에 지금 문서를 보여 주는 함수, 엔진 수치를 넘기는 함수(상태 막대와 엔진 탭이 같은 값을 쓴다).
  - 예제가 돌려주는 것: `reset()`(재생 막대 리셋)과 `destroy()`(정리). 시작이 끝나기 전에 신호가 중단되면 예제가 늦게 생긴 자원을 바로 정리한다.
  - 틀이 맡는 것: 재생 막대, 실행 상태 점(불러오는 중·실행·오류), 캔버스 비율 맞춤, 렌더러 전환(다시 시작), 전체 화면, 이전/다음, 아래 패널 탭, 상태 막대.
  두 번째 예제('충돌과 트리거')에서 더한 계약:
  - `display(options)`: 재생 막대 '표시' 메뉴의 체크 항목(이름·처음 값·바뀔 때 함수). 넘기지 않으면 메뉴가 없다. 다시 시작하면 비운다.
  - `event(entry)`: 아래 패널 '이벤트' 탭의 한 줄(종류·대상·들어감/나감/그 밖). 카탈로그 `events: true`인 예제만 탭이 있고,
    틀은 이번 실행의 최근 200줄과 받은 수를 탭에 보인다. 예제는 매 프레임 상태가 아니라 바뀐 순간만 넘긴다.
  - 엔진 수치의 `extra`: 예제별 추가 수치. 상태 막대 끝과 엔진 탭에 같은 값으로 붙는다.
  세 번째 예제('벽돌 깨기')에서 더한 계약:
  - 세션의 `setPaused(paused)`: 있으면 재생 막대에 일시정지·계속 버튼이 나온다. 리셋은 멈춘 게임을 다시 진행시킨 뒤 처음으로 돌린다.
  - 이벤트 줄의 대상(`detail`)은 씬 id 같은 문자열 또는 한국어·영어 문구다.
  - 목록·첫 화면·예제 사이 이동은 주소만 바꾸고(`history`) 틀은 다시 그리지 않는다.
- 옛 주소(`/starter-runtime/`, `/breakout/`, `/platformer/`, `/topdown-shooter/`, `/pixel-art/`, `/physics-sandbox/`)는
  새 첫 화면으로 보내는 안내 페이지로 남겨 외부 링크가 404가 되지 않게 한다.
- `build-pages`는 예제 앱 대신 `examples/site/dist`를 루트에 복사하고, Studio와 문서는 지금처럼 만든다.
  갤러리 생성기(`scripts/build/example-gallery.mjs`, `examples/shared/gallery/gallery.*`)와 그 테스트, 발행된 예제에서 썸네일을 찍던
  `pnpm thumbnails:examples`는 지운다. 옛 예제 앱이 쓰는 카탈로그·썸네일은 검사 데이터로 남긴다.
- 검사: 옛 사이트 통합 검사 `smoke:example-suite`는 새 사이트 검사 `smoke:example-site`로 바꾼다. 옛 예제 앱의 smoke
  (`smoke:feature-examples`, 게임·물리 렌더 smoke)는 검사 데이터로서 그대로 둔다. Pages 산출물 검사와 배포 후 경로 검사는
  새 첫 화면·Studio·문서·옛 주소 안내로 바꾼다.

    틀이 예제가 끝난 뒤 그 캔버스의 WebGL2 컨텍스트를 놓아준다(예제를 오가도 브라우저 컨텍스트 수 제한에 걸리지 않게).
  - `smoke:example-site`에 화면·조작·끌기·씬 파일·리셋·렌더러 전환·뒤로/앞으로·떠날 때와 시작 중 이동 시 자원 해제 검사를 더했다.
- 아래 패널 높이 조절과 목록·인스펙터의 너비 조절·접기를 넣었다(위 '패널 크기와 접기').
- 사이트 틀과 스프라이트 예제에 한국어·영어 전환을 넣었다. 언어를 바꿔도 예제 실행과 조작값, 열린 탭을 유지한다.
- 두 번째 예제 '충돌과 트리거'(`?example=collision`)를 넣었다(2026-11-24 사용자 승인).
  - 장면(640 × 384): 판 위 바깥 벽 4개와 안쪽 벽 2개(단단한 static body), 에너지 3개(트리거, 닿으면 엔진이 수집해 지운다),
    빨간 구역 1개(트리거), 로봇(kinematic body, 단단한 충돌체). 에셋은 자체 제작 그림이다(아래 그림 항목).
  - 이동: 방향키·WASD, 또는 실행 화면을 누르고 있으면 그쪽으로. 예제는 로봇 body에 속도만 주고, 벽에 막혀 미끄러지는 것은 엔진이 한다.
  - 해 보기: 이동 속도, 로봇 충돌체 모양(사각형·원), 안쪽 벽(단단함·트리거). 바꾸면 지금 로봇 위치와 남은 에너지를 유지한 문서를 다시 적용한다.
  - 볼 것: 단단한 벽은 막고 트리거는 통과하며 이벤트만 낸다. 안쪽 벽을 트리거로 바꾸면 같은 자리에서 막히지 않고 이벤트가 난다.
  - 틀에 더한 것(이 예제가 처음 쓴다): 재생 막대 '표시' 메뉴(예제가 넘긴 체크 항목, 여기서는 엔진 물리 디버그 선의 충돌 모양·접촉),
    아래 패널 '이벤트' 탭(카탈로그에 이벤트를 쓴다고 표시한 예제만, 최근 것부터 시간·종류·대상), 상태 막대의 예제별 추가 수치.
  - 상태 막대의 접촉·트리거 수는 예제가 시작·끝 이벤트로 센 지금의 쌍 수다. 엔진의 `frame.physics.collision*Pairs`는
    한 출력 프레임 안의 물리 단계마다 더한 값이라(고정 시간 단계가 두 번 돌면 2) 지금 겹친 수로 쓰지 않는다.
  - 그림은 `scripts/assets/build-example-collision.mjs`가 만든다(바닥 타일 한 장, 9-slice 벽, 줄무늬 위험 구역, 4프레임 에너지, 옛 플레이그라운드 로봇 시트 복사).
    바닥과 구역은 화면 크기 그대로 그려 늘어나지 않고, 벽은 늘려도 깨끗한 9-slice다. 로봇은 엔진의 이동 애니메이션 연결로 움직일 때 걷는다.
    수집한 자리에 '+1'이 잠깐 뜨는 것은 페이지 장식이다. 카드 썸네일은 이 예제 화면을 찍은 것이다.
- 세 번째 예제이자 첫 게임 데모 '벽돌 깨기'(`?example=breakout`)를 넣었다(2026-11-24 사용자 승인).
  - 방식: 엔진 내장 Breakout(`useBreakoutGame()`)은 설정이 없고 흰 사각형으로 그려서 쓰지 않는다. 씬 문서와 물리로 만들고,
    공 반사·막힘은 엔진, 점수·목숨·벽돌 지우기 같은 게임 규칙은 예제 코드가 엔진 충돌 이벤트를 받아 처리한다.
  - 장면(640 × 384): 위·양옆 벽(static), 벽돌 10 × 5(static, 줄마다 색), 패들(kinematic), 공(dynamic, 중력 0·튕김 1·마찰 0),
    화면 아래 밖의 놓침 구역(트리거). 그림은 `scripts/assets/build-example-breakout.mjs`가 만든다.
  - 조작: 마우스 가로 위치나 방향키·A/D로 패들, 클릭이나 Space로 공 발사. 패들도 속도로 움직여 벽에서 엔진이 멈춘다.
  - 규칙: 공이 벽돌에 닿기 시작하면 벽돌을 지우고 점수를 더한다. 패들에 닿으면 맞은 위치에 따라 반사 각도를 정한다(가운데는 위, 끝은 비스듬히).
    놓침 구역에 들어가면 목숨이 준다. 공 속도는 매 프레임 설정값으로 맞추고 너무 눕지 않게 한다. 다 깨면 클리어, 목숨이 없으면 게임 오버.
  - 해 보기: 공 속도(바로 적용), 패들 너비, 벽돌 줄 수(새 판 시작). 표시 메뉴: 충돌 모양(처음엔 끔). 이벤트 탭: 벽돌·패들·놓침·클리어.
  - 상태 막대 추가 수치: 점수, 목숨, 남은 벽돌. 점수·목숨과 시작·끝 안내는 실행 화면 위에 예제가 그린다.
  - 틀에 더한 것: 게임용 재생 막대의 일시정지·계속 버튼(예제 세션이 `setPaused`를 주면 나온다. 씬 시뮬레이션만 멈추고 그리기는 계속).
  - 물리 단계의 연속 충돌(CCD)은 끈다(`configureAutoRigidBodyStep({ continuous: false })`). 공은 한 단계에 최대 8px(480px/s, 1/60초)만 움직여
    벽·벽돌·패들을 건너뛸 수 없다. CCD를 켜면 아래 엔진 문제로 게임이 멈춘다.
  - 같은 발사·같은 패들 위치면 고정 시간 단계라 공의 길이 매번 같다. smoke는 이 성질로 첫 벽돌(brick_4_5)과 첫 놓침을 확인한다.
- 별도 후보(엔진): Data Scene의 planar native 물리에서 연속 충돌을 켠 채 dynamic 공이 static 상자 사이의 한 칸 틈(지운 벽돌 자리)으로
  들어가면 엔진 프레임 단계가 `physics capacity exceeded`를 던지고 시뮬레이션이 멈춘다. 지우지 않고 body를 끄고 옮겨도 같고,
  연속 충돌을 끄면 생기지 않는다. 재현: 벽돌 깨기에서 CCD를 켜고 넓은 패들, 가만히 둔 채 세 번 발사(약 5초).
  `physics3d`의 궤적 작업 한도(`TrajectoryError::WorkLimit`)가 같은 오류 문구로 보고되는 것으로 보인다. 엔진 변경이라 따로 진행한다.

  그 예제의 화면·조작·자원 해제 검사를 `smoke:example-site`에 더한다. 새 화면 요소('표시' 메뉴, 선택한 물체, 게임용 재생 막대)는
  그것을 쓰는 예제와 함께 계약에 더한다.

## 검증

- 예제마다: `pnpm lint`, 새 사이트 빌드, `pnpm build:pages`, `pnpm validate:pages-artifact`, `pnpm smoke:example-site`.
- 1단계: `pnpm lint`, 새 사이트 빌드, `pnpm build:pages`, `pnpm validate:pages-artifact`, `pnpm smoke:example-site`
  (첫 화면·목록·검색·서랍·없는 예제 안내·옛 주소 안내·1440/1024/390/320px 넘침 없음·JavaScript 오류 없음),
  남겨 둔 예제 검사 데이터를 쓰는 smoke가 그대로 통과하는지.
- 옛 사이트 통합 검사(`smoke:example-suite`)가 하던 이전 예제 앱의 Pages 수명 주기 검사(시작 중 취소·자원 해제·시나리오 요청 순서)는
  그 앱들이 발행되지 않으므로 함께 지웠다. 기능 실험실의 수명 주기·복구 검사는 `smoke:feature-examples`에 남아 있고,
  새 사이트에는 예제를 추가할 때 그 예제의 수명 주기 검사를 함께 넣는다.
