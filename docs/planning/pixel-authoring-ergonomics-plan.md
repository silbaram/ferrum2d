# 도트 편집 편의성 고도화 개발 계획

기준일: 2026-10-31
상태: 후속 단계 구현 미착수
다음 작업: 2단계 자동 임시 저장·복구

## 목표와 기준

에디터 안에서 직접 만든 도트를 부분 수정하고 재사용하는 시간을 줄이며, 미저장 작업을 복구할 수 있게 한다.
기본 제작·선택 영역 편집·레이어·프레임·태그·어니언 스킨·노멀 생성·2D/HD-2D 적용은
[현재 도트 계약](../engine/data-scene-authoring.md#에디터-내장-도트-제작)을 사용한다. 이 기능들을 신규 개발 항목으로 다시 등록하지 않는다.

Aseprite는 편집 동작과 알고리즘의 참고 대상이다. 외부 도구 설치나 Aseprite 파일 호환성은 이번 목표에 포함하지 않는다.
도트 이미지 편집은 기존 에셋 작성 보조 도구의 범위이며 게임 behavior/FSM/timeline 편집으로 확장하지 않는다.

## 우선순위와 진행 상태

| 순서 | 우선순위 | 단계 | 현재 한계 | 상태 |

남은 작업 순서는 2→3→4→5→6이다. 단계별 구현·회귀 검증·문서 동기화를 끝낸 뒤 다음 단계로 이동한다.
단계에 착수할 때 상태와 다음 작업을 갱신하며, 계획에 적힌 항목을 구현 완료로 해석하지 않는다.

## 공통 구현 원칙

- 픽셀 문서 모델이 원본과 Undo를 소유하고 canvas/UI는 입력·선택·미리보기를 담당한다. 게임 simulation과 Wasm render ABI는 변경하지 않는다.
- 픽셀 편집 대상은 선택 프레임의 선택 이미지 레이어다. 숨김·잠금·재생 중 편집 차단과 고정 atlas의 선택 rect 제한을 유지한다.
- 선택·드래그·도형 미리보기는 원본을 확정하지 않는다. 확정은 한 Undo, Escape·포인터 취소·포커스 상실은 이전 상태 복원이다.
- 기존 v1~v5 원본, stable layer/frame/tag/clip ID, straight-alpha RGBA와 투명 픽셀의 RGB를 보존한다.
- 초기 범위는 기존 문서·cel·revision·이력 예산 안에서 구현한다. 상한을 늘리기 전에 실제 비용과 실패 사례를 측정한다.
- 원본·프레임 구성이 바뀌면 기존 노멀의 source/hash 근거를 다시 확인한다. 오래된 pair를 새 원본에 적용하지 않으며 재생성·검증된 cache 재사용 경로를 사용한다.
- 씬·GPU 자산 변경은 기존 명시적 등록/적용/저장 경로를 사용한다. 그림을 편집하거나 복구했다는 이유로 씬을 자동 변경하지 않는다.
- 새 production 의존성은 기본 전제로 삼지 않는다. 필요하면 대안과 비용을 먼저 문서화한다.

## 2단계 — 자동 임시 저장·복구

### 범위

- 편집 확정 후 debounce하는 원본 checkpoint 저장. 첫 구현은 브라우저/WebView의 IndexedDB를 검토하며 게임 프로젝트 파일은 자동으로 덮어쓰지 않는다.
- 재실행 시 복구 가능한 작업 표시와 복원·폐기 선택. 픽셀·레이어·프레임·태그·팔레트를 기존 원본 형식으로 복원한다.
- 복구 key는 프로젝트/문서와 편집 세션을 구분한다. 복수 탭이나 늦은 비동기 결과가 다른 원본을 덮어쓰지 않게 한다.
- 우선 세션당 마지막 유효 checkpoint 1개를 보관한다. 전체 보관량·오래된 세션 만료·동일 프로젝트 충돌 정책을 구현 전에 확정한다.

### 완료 조건

- reload·비정상 종료를 모사한 재열기에서 마지막 완료 checkpoint를 복원하며 저장 중이던 불완전 자료는 채택하지 않는다.
- 복구 입력에도 기존 원본 검증과 byte/cel 상한을 적용한다. quota 초과·storage 거절·손상 자료는 상태를 표시하고 수동 내보내기를 유지한다.
- 복구는 프로젝트 저장 완료나 씬 적용으로 표시하지 않는다. 원본 dirty와 노멀 재검증이 유지된다.
- 프로젝트 A/B 격리, 복수 탭, 복구 폐기·정상 저장·문서 종료의 수명을 검증한다.

## 3단계 — 브러시·대칭·도형

### 범위

- 연필/지우개 크기와 사각 브러시, 가로/세로 대칭.
- 직선·사각형·원/타원, 윤곽선/채움 선택과 드래그 미리보기.
- 대칭 기준은 활성 frame rect를 사용한다. 최초 범위는 중앙 축이며 축 직접 이동은 후속 후보로 둔다.

### 완료 조건

- 홀수/짝수 치수·축 위 픽셀·atlas offset에서 대칭이 일치하고 중복 지점은 한 번만 수정한다.
- 빠른 포인터 이동과 화면 밖 좌표의 비용을 제한하며 frame rect 밖을 쓰지 않는다.
- 한 stroke/도형은 한 Undo이고 취소·잠금·숨김·재생 차단이 기존 도구와 같다.
- 선택 영역이 있으면 그 영역으로 편집을 제한한다. 기존 1픽셀 도구의 결과를 보존한다.

## 4단계 — 팔레트 편집

### 범위

- 색 추가·수정·삭제·순서 변경, 최근 사용색과 명시적 팔레트 가져오기/내보내기.
- 색 일괄 교체는 선택 cel/선택 영역/문서 전체 중 적용 범위를 표시하고 확정한다.
- 최초 범위는 기존 RGBA 원본과 팔레트 metadata를 사용한다. indexed color 원본이나 자동 색상 양자화는 별도 후보로 둔다.

### 완료 조건

- 팔레트 편집을 원본 저장·재열기·dirty·Undo에 포함하고 기존 palette 입력 상한을 유지한다.
- 팔레트 색 수정과 실제 픽셀 색 교체를 구분한다. 투명도·다른 프레임·잠금 레이어 처리 정책을 표시한다.
- 원본 hash가 바뀐 경우 PNG가 같더라도 기존 노멀 provenance를 조용히 새 원본에 연결하지 않는다.
- 한글/영문·키보드 색 선택과 현재 색·알파 입력 동작이 유지된다.

## 5단계 — 캔버스 크기 변경

### 범위

- 기준점을 지정한 여백 확장·자르기, 변경 전후 크기와 잘리는 영역의 미리보기.
- 모든 frame/layer에 같은 치수와 offset을 적용한다. 픽셀 보간 크기 변경은 최초 범위에서 제외한다.
- 고정 atlas v4는 layout 재작성 설계 전까지 크기 변경을 차단한다.

### 완료 조건

- 기존 한 변·전체 cel·원본 byte 상한을 변경 전에 검사하고 실패하면 원본과 이력을 보존한다.
- stable layer/frame/tag/clip ID와 기존 픽셀 RGBA를 유지하며 Undo로 치수와 모든 cel을 함께 복원한다.
- atlas/animation UV는 명시적 새 자산 적용에서 재계산한다. 씬의 크기·pivot·collider/body를 자동 수정하지 않는다.
- 이전 노멀은 재생성/검증 전 적용을 차단하고 기존 애니메이션 변경 검토 경로를 유지한다.

## 6단계 — 실제 크기 미리보기

### 범위

- 확대 편집 옆의 접이식 1배율/2배율 미리보기와 선택 태그 애니메이션 재생.
- 소스 1픽셀을 CSS 1픽셀로 표시하는 1배율이다. 실제 게임 카메라·오브젝트 크기는 기존 게임 미리보기로 확인한다.
- 기존 합성 결과와 프레임 재생 시계를 재사용하며 별도의 게임 runtime이나 노멀 생성 job을 만들지 않는다.

### 완료 조건

- DPR 1/2에서 CSS 배율이 같고 nearest 표시로 픽셀 경계를 보존한다.
- 편집·Undo·레이어 표시·프레임·태그 변경이 반영되며 UI 조작만으로 원본/dirty/Undo가 바뀌지 않는다.
- 탭 전환·비활성·창 blur·종료에서 RAF와 canvas 자원을 정리한다.
- 좁은 화면에서 접을 수 있고 편집 영역의 스크롤·키보드 포커스를 해치지 않는다.

## UI 구성

- 왼쪽은 선택/그리기 도구, 상단은 현재 도구의 크기·대칭·확정/취소 등 관련 옵션만 표시한다.
- 내보내기·복구·고급 편집은 메뉴로 묶는다. 모든 기능을 상단 고정 버튼으로 추가하지 않는다.
- 프레임/태그·이미지 레이어 패널을 재사용하고, 아이콘에는 한글/영문 tooltip·단축키·접근성 이름을 제공한다.
- Pixelforge의 기존 토큰·포커스·선택 표시를 사용한다. 선택 영역과 씬 객체 선택은 시각적으로 구분한다.

## 코드와 검증 경로

원본/Undo는 `placementPixelDocument.ts`, 입력/표시는 `placementPixelCanvas.ts`, 도구 연결은
`placementPixelTool.ts`가 기준이다. 복구는 별도 storage 모듈로 분리하고 문서 모델에 브라우저 API를 넣지 않는다.
필요한 순수 픽셀 연산도 문서 모델에서 분리하되 기존 source/schema/patch 경계를 유지한다.

구현 단계별 검증은 [Smoke Check](../development/quality/smoke-check.md)를 기준으로 다음 범위를 선택한다.

| 변경 범위 | 검증 |
| --- | --- |
| 원본·Undo·연산 | `pnpm test:pixel-authoring`, 해당 단계의 경계/취소/원자성 회귀 추가 |
| UI·입력 | `pnpm lint`, `pnpm --filter @ferrum2d/placement-viewer build`, `pnpm smoke:pixel-authoring`, 한글/영문·좁은 화면·DPR 1/2 캡처 |
| 원본 저장·복구 | storage 실패/교차 세션 회귀, `pnpm test:native-normal-project`, `pnpm smoke:pixel-project` |
| 자산 적용·노멀 | `pnpm build` 후 `pnpm smoke:pixel-normals`, `pnpm smoke:pixel-normals-project`, `pnpm smoke:sprite-normal-2d` |
| 문서·저장 계약 | 기존 원본 fixture 호환, `pnpm validate:docs-links`, `pnpm build:pages`, `pnpm validate:pages-artifact` |

새 검증을 만들면 실제로 실행하는 script/CI 경로와 실패 artifact를 연결한다. 계획 작성만으로 검증 gate를 추가하지 않는다.
새 source 형식이나 공개 API가 필요하면 구현 전에 호환·migration을 정하고 해당 contract 문서를 함께 갱신한다.
Rust/ABI를 변경하지 않는 단계에서는 불필요한 native 구조 변경을 하지 않는다.

## 별도 후속 후보와 문서 수명

- AI 도트 생성은 텍스트/스케치 입력·결과 선택·원본 등록·비용/인증/출처를 별도 설계할 후보다. 이번 6단계에는 포함하지 않는다.
- 이력의 차분 저장, 다중 cel 일괄 편집, 임의 각도/이미지 확대, OS 클립보드는 실제 요구와 예산을 확인한 뒤 검토한다.
- 완료한 단계는 현재 계약·검증 문서에 반영하고 이 문서에서는 남은 단계만 유지한다. 6단계가 모두 끝나면 계획을 삭제하고 색인의 링크도 정리한다.
